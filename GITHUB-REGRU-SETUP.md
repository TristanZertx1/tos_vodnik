# GitHub → REG.ru

## GitHub Actions secrets

Откройте **Settings → Secrets and variables → Actions → New repository secret** и добавьте три секрета с точными именами:

- `REG_FTP_SERVER` — адрес FTP-сервера REG.ru.
- `REG_FTP_USERNAME` — имя FTP-пользователя.
- `REGRU_FTP_PASSWORD` — пароль FTP-пользователя.

Имена должны совпадать с workflow `.github/workflows/deploy-regru.yml`. Не добавляйте значения секретов в файлы репозитория, issues или логи.

## Защищённое подключение

Workflow использует явный FTPS (explicit TLS) на порту 21. До включения автоматической публикации убедитесь в панели REG.ru, что для вашего FTP-аккаунта доступен FTPS. Обычный FTP не шифрует пароль и содержимое файлов. Если тариф/сервер не поддерживает FTPS, настройте поддерживаемый защищённый способ передачи отдельно; не возвращайте парольную передачу по обычному FTP.

## Публикация

После push в `main` workflow собирает статическую часть сайта и PHP API, затем синхронизирует их с `/www/tos-vodniki.ru/`.

Из сборки исключаются:
- `api/config.php` и `api/config.test.php` — конфигурация и секреты сервера;
- `api/setup.php` — одноразовый установщик, который нельзя повторно публиковать после первоначальной настройки.

При первой установке загрузите `api/setup.php` на сервер вручную только на время установки, выполните установку и сразу удалите файл. Не храните установщик доступным на публичном сервере после настройки.

## Перед включением workflow

1. Проверьте наличие `api/config.php` на сервере и корректность параметров MySQL.
2. Проверьте, что FTPS подключение работает для указанного FTP-аккаунта.
3. Запустите workflow вручную на тестовой ветке/окружении, если оно настроено, и проверьте результат.
4. Не используйте production-деплой для проверки изменений без резервной копии сайта и базы данных.
